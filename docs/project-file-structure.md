# Music Player Project File Structure

# `/`
Contains root configuration files
- `package.json` - Project dependencies and npm scripts
- `tsconfig.json` - TypeScript configuration for the whole project
- `tsconfig.node.json` - TypeScript configuration for build tooling and Vite config files
- `vite.config.ts` - Vite build and dev server configuration
- `electron-builder.json5` - Configuration for packaging the app into a distributable installer
- `index.html` - The HTML entry point that loads the React app

# `electron-startup/`
Starts the Electron app, sets up the window, and connects the frontend to the backend
## `main.ts`
The entry point that starts the entire app
- Starts the Electron app
- Creates the app window
- Connects to the database
- Starts the file watcher
- Registers all IPC communication handlers
- Manages app startup and shutdown
## `preload.ts`
Exposes a bridge bteween the main and renderer processes, letting the frontend talk to the backend without exposing any dangerous APIs directly to the browser
## `electron-env.d.ts`
Defines TypeScript type definitions of the global values injected to the renderer process by the preload script

# `src/`
All application source code, split between the backend (main process) and frontend (renderer process)

## `backend/`
Contains all scripts related to the backend process of the app that have full access to your computer to read files, talk to the database, call external APIs, and manage background tasks

### `database/`
Contains everything related to the SQLite database
- `database-startup.ts` - Starts the database connection and exposes it
- `schema.ts` - Defines the single source of truth for all the database tables and their columns

#### `migrations/`
Contains database change scripts that run automatically on startup to keep the database schema up to date (Automatically generated by Drizzle)

#### `repositories/`
Contains a file for each domain (e.g. tracks, tags, playlists), each containing all the relevant database queries for that domain. These are called by the IPC handlers so they don't have to call SQL queries directly

### `ipc-handlers/`
Contains all the IPC handlers that respond to frontend messages with one file per feature domain 

### `job-queue/`
Defines a background task queue to queue heavy work that would freeze the application
- `queue.ts` - Creates and manages the job queue: adding jobs, running them in order, and reporting progress back to the frontend
- `types.ts` - Defines all TypeScript types for jobs

#### `job-handlers/`
Contains all jobs and what they do when called
- `extract-metadata.ts` - Reads song info (title, artist, album, etc.) from audio files
- `fetch-album-art.ts` - Looks up and saves missing album artwork from the internet
- `match-spotify-tracks.ts` - Tries to match your Spotify songs to local files on your computer
- `spotify-import.ts` - Pulls your liked songs, playlists, and audio data from Spotify

### `services/`
Contains any general utility helper modules used by multiples systems in the backend
- `file-watcher.ts` - Watches your music folder for new, deleted, or moved files and tells the frontend when something changes
- `spotify.ts` - Handles logging into Spotify and making API requests
- `store.ts` - Saves and reads app settings that need to persist between sessions (like your music folder path)
- `window.ts` - Creates and manages the app window

## `frontend/`
The React frontend of the app, containing all files handled by rendered process

### `src/`
The React application source code

#### `audio-playback-logic/`
Handles audio playback logic separate from React components
- `music-player.ts` - The main music player instance. Handles play, pause, skip, seek, and volume
- `song-previewer.ts` - A separate independent player just for song previews (hover previews, preview button, preview keybind). Runs completely separately so previews never interrupt what's playing

#### `components/`
All React components grouped by the feature domain they belong to besides top-level views. .tsx and .module.css are stored side-by-side

##### `common/`
Generic reusable components with no domain knowledge: buttons, modals, inputs, icons

##### `layout/`
The persistent app shell components: sidebar, now-playing bar, main content area

##### `library/`
Components for browsing and filtering your music library

##### `player/`
Playback control components and the now-playing display

##### `playlists/`
Components for viewing and managing playlists

##### `spotify/`
Components for the Spotify login and import flow

##### `tagging/`
Components for creating tags, applying them to songs, and viewing tag suggestions

#### `hooks/`
Custom React hooks that wrap complex logic so components stay clean

#### `ipc-callers/`
Contains all the IPC calls that are sent to the backend with one file per feature domain 

#### `data-stores/`
Zustand stores that hold all the app's live state with one store per feature domain

#### `styles/`
Global CSS files
- `global.css` - App-wide base styles: resets, layout, dark mode
- `tokens.css` - Design system values as CSS variables: colors, spacing, fonts

#### `views/`
Top-level page components, one per sidebar section. Each view composes smaller components and hooks to build a full page

## `preload-utils/`
Contains any preload-related utilities used by both the frontend and backend

## `shared-types-and-constants/`
Contains types and constants used by both the frontend and backend

# `docs/`
Contains all project documentation .md files for anything from requirements, file structure, architecture, and design
- `music-player-requirements.md` - The full feature spec for the app
- `project-file-structure.md` - This file
- `ipc-channels-api.md` - A reference for every IPC channel: what it does, what it accepts, and what it returns
- `main-rendered-ipc-processes-architecture-design.md` - Explains what the main process owns vs. what the renderer owns, and why they're kept separate
- `sqlite-drizzle-database-architecture-design.md` - How the database is set up and organized
- `job-queue-design.md` - How the background job queue works
- `chokidar-file-watcher-architecture-design.md` - How the app detects changes to your music folder
- `electron-store-architecture-design.md` - How and where app settings are saved
- `howler-js-architecture-design.md` - How audio playback is managed

# `public/`
Contains static assets bundled with the app like icons, logos, and default images

# `dist-electron/`
Compiled build output for the Electron main process that is auto-generated
